# macOS 菜单栏刷新

行情推流和设置保存都更新 Rust 共享状态，再调用 `bar::request_render`。
它合并同一批刷新请求，在主线程读取当前状态并更新 AppKit。
价格由行情推送驱动；没有新报价时无需每秒重复绘制。

菜单由 macOS 绘制层持有，通过与 Tauri 同版本的 `tray-icon` / muda
创建和挂载。菜单事件仍由 Tauri 的全局菜单事件处理器转发。
菜单文字、状态说明和菜单栏价格都能在下拉菜单关闭时更新。
填了交易所 API Key 时，菜单最上面多一行总资产和一条分隔线，自选行和状态行的
下标随之后移（`Layout::row`）；按下状态项时会请求刷新超过 15 秒的持仓。

总资产这一行带子菜单，内容由 `bar::Holdings::slots` 决定（两个平台共用）：
「查看持仓…」、24h 盈亏、各账户（多于一个时）、最大的几项资产、合约仓位、
以及末尾的「更新于」说明。子菜单用 muda 的 `Submenu` 建，分区标题是 AppKit 自己的
`sectionHeaderWithTitle`（macOS 14+），建好后按下标插进 NSMenu；行的富文本和主菜单
一样由 `apply` 按下标就地更新，列宽（`Table`）只增不减，所以打开着的子菜单不会
因为价格跳动而抖。行数或分区变化才重建整份菜单（`Layout.holdings` 是 `Shape`）。
子菜单里的每一行都打开持仓窗口。

「菜单栏显示总资产」打开时（`Settings::holdings_in_bar`，会取消自选的置顶），
状态项显示的是总资产：单行 `总资产 128,431`，开了涨跌幅就是双排图像，和自选
的显示方式一样；某个账户读取失败时前面带 ⚠︎。

菜单里的文字按应用的语言说（见 [i18n.md](i18n.md)）。`Layout` 带着语言，切换语言后下一次绘制整份重建菜单，子菜单的分区标题也随之重建。

涨跌色不是系统的红绿，而是 Candlewick 自己的（见 [design.md](design.md)）。
菜单文字由系统绘制，我们只给涨跌数字上色：`ticker::trend_color` 用
`colorWithName:dynamicProvider:` 造动态颜色，按当前绘制外观返回浅色或深色值，
所以菜单和双排图像在切换外观时无需重建。

## 0.7.0 冻结回归

0.5.0 到 0.6.0 的依赖升级把 `tray-icon` 从 0.24.2 升到了 0.25.1。
新版只在打开下拉菜单期间设置 `NSStatusItem.menu`，关闭后将它清空。
原实现从这个属性读取菜单，取不到就退出整个绘制过程，导致价格和设置
只在点击托盘后才呈现。不要将这个临时属性当成应用持有的菜单。

2026-09-27 本机排查时，正式版未点击托盘也持续接收网络数据。
正式版没有注册应用日志输出器，系统日志不能用于确认具体报价；调试版
可用 `CANDLEWICK_LOG=trace` 查看连接、菜单行和菜单栏绘制。

## 回归验证

在 macOS 登录会话中运行：

```sh
cd src-tauri
cargo test --locked --test macos_bar
```

测试使用真实 AppKit 和 Tauri，在进程主线程运行，不启动行情连接、
不读取用户凭证、不写设置。始终不打开下拉菜单，检查连续报价、菜单行、
名称显隐、双行显示、配色更新、切换固定标的和清空自选的原生显示结果；
然后塞入一个有持仓的账户，检查总资产行、子菜单的各行和分区标题、价格变动
时子菜单原地更新（NSMenu 指针不变），总资产在状态项上的单行和双排显示，
以及换成日文后菜单和子菜单分区标题整份换成日文。
恢复旧的 `NSStatusItem.menu` 提前返回逻辑时，首个价格断言应失败。
此测试也随 `cargo test --locked` 运行，在 Windows 上跳过。
