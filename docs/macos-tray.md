# macOS 菜单栏刷新

行情推流和设置保存都更新 Rust 共享状态，再调用 `bar::request_render`。
它合并同一批刷新请求，在主线程读取当前状态并更新 AppKit。
价格由行情推送驱动；没有新报价时无需每秒重复绘制。

菜单由 macOS 绘制层持有，通过与 Tauri 同版本的 `tray-icon` / muda
创建和挂载。菜单事件仍由 Tauri 的全局菜单事件处理器转发。
菜单文字、状态说明和菜单栏价格都能在下拉菜单关闭时更新。
填了交易所 API Key 时，菜单最上面多一行总资产和一条分隔线，自选行和状态行的
下标随之后移（`Layout::row`）；按下状态项时会请求刷新超过 15 秒的持仓。

## 0.7.0 冻结回归

0.5.0 到 0.6.0 的依赖升级把 `tray-icon` 从 0.24.2 升到了 0.25.1。
新版只在打开下拉菜单期间设置 `NSStatusItem.menu`，关闭后将它清空。
原实现从这个属性读取菜单，取不到就退出整个绘制过程，导致价格和设置
只在点击托盘后才呈现。不要将这个临时属性当成应用持有的菜单。

2026-09-27 本机排查时，正式版未点击托盘也持续接收网络数据。
正式版没有注册应用日志输出器，系统日志不能用于确认具体报价；调试版
可用 `CANDLEWICK_LOG=trace` 查看连接、菜单行和菜单栏绘制。

## 回归验证

在 macOS 登录会话中运行：

```sh
cd src-tauri
cargo test --locked --test macos_bar
```

测试使用真实 AppKit 和 Tauri，在进程主线程运行，不启动行情连接、
不读取用户凭证、不写设置。始终不打开下拉菜单，检查连续报价、菜单行、
名称显隐、双行显示、配色更新、切换固定标的和清空自选的原生显示结果。
恢复旧的 `NSStatusItem.menu` 提前返回逻辑时，首个价格断言应失败。
此测试也随 `cargo test --locked` 运行，在 Windows 上跳过。
