# 界面语言

Candlewick 说三种语言：English、简体中文、日本語。托盘 / 任务栏和下拉菜单、macOS 的应用菜单、窗口标题、错误与状态说明、三个窗口，全部跟着同一个语言走。

## 谁决定语言

Rust 决定（`src/i18n.rs`）。

- 设置 → 通用 → 语言：「跟随系统」或三种之一，存在 `Settings.language`（`system`、`en`、`zh-CN`、`ja`）。
- 跟随系统时，取系统首选语言列表里第一个应用会说的（`sys-locale`：macOS 是 `CFLocaleCopyPreferredLanguages`，会读到「系统设置 → 通用 → 语言与地区 → 应用程序」里单给 Candlewick 选的语言；Windows 是显示语言列表）。繁体中文不算简体中文，和系统匹配 bundle 本地化时一样，交给列表里的下一个语言；都不会说就用英文。
- `Language` 是 `System` 或 `Only(Locale)`，写进设置文件时就是 `system` 或语言标签。
- 启动时先定语言再建托盘；改设置时保存流程依次：记下语言（macOS，见下文）、切换、改窗口标题、重建 macOS 应用菜单。托盘菜单的 `Layout` 带着语言，语言一变下次绘制就整份重建；Windows 的下拉菜单开着时不换，等下次打开。

## 文字放在哪

一套目录：`locales/<tag>/<surface>.json`，`<tag>` 是 `en`、`zh-CN`、`ja`（对应 `Locale::En`、`Locale::ZhCn`、`Locale::Ja`），`<surface>` 是：

| surface | 谁说 |
|---|---|
| `app` | 托盘与菜单、应用菜单、窗口标题、错误与状态说明；外加 `common`，即各窗口也要用的词：数据源名、总资产、24h 盈亏、多空、更新于、正在读取 |
| `common` | 各窗口共用的零碎：加载中、市场名、K 线周期缩写、窗口按钮的名字 |
| `settings` / `chart` / `holdings` | 对应的窗口 |

`build.rs` 把一种语言的各 surface 合并成一个目录；key 是合并后的带点路径（`t!("settings.title")`），surface 名不进 key。同一个 key 出现在两个 surface 里是构建错误。目录按 surface 拆开，是为了各窗口的改动不挤在同一个文件里。

约定：

- 占位符写作 `%{name}`。
- 两个平台说法不同的消息，Windows 那句加 `_windows` 后缀（「菜单栏」与「任务栏」）；`build.rs` 按编译目标把对应的那句编进去，代码只写 `t!("error.onePinned")`。
- 不用复数后缀（`_one` / `_other`）：`t!` 不会按数选句，单数的说法是另一条 key（`ths.countOne` 与 `ths.count`）。中文、日文没有单复数之分，两条 key 写同一句。
- key 是 camelCase，`_` 只用来接平台和单数这类的变体。

## 编译出来的 `t!`

`build.rs` 把 `locales/` 编译成 `t!` 宏（每条消息一条规则）和每条消息一个函数，按当前语言返回：没有占位符的是 `&'static str`，有的是 `format!` 出来的 `String`。所以数据源名、交易时段、菜单分区标题这些词是静态字符串，托盘每秒重绘不为它们分配内存。占位符按英文里出现的顺序写。于是：

- key 写错、占位符名写错或漏写，都编译不过，报错直接说 `locales/en has no message "…" with these placeholders`；
- 某语言缺一条、多一条，或占位符和英文不一致，构建失败；
- 运行时没有查表，也没有依赖。

只进日志的文字（重连原因、路由）用英文，不进目录。

## 数据不带文字

Rust 交给 AI 接口的是代码和数字，由显示它的一方翻译：钱包（`spot`、`usdFutures`…）、合约类型（`usdtPerpetual`、`coinFutures`…）、`sizeUnit` 为 null 表示张数、交易时段（`pre`、`post`、`overnight`）、K 线周期只给秒数、`statsSpan`（`rolling24h` 或 `today`）、行情窗口的 `source` 是数据源 id、`link` 只有地址。AI 接口自己的拒绝信息是英文，接口不随界面语言变。

例外是成句的说明：错误信息、搜索的 `notes`、长桥给的行情包名和提示。它们在 Rust 里产生时按当时的语言写好；长桥的请求带 `accept-language`（中文界面 `zh-CN`，其余 `en`），股票名在中文界面取中文名、其余取英文名（添加时取，存在自选里）。同花顺只给中文名，任何界面下都是中文；它自己的报错原文也是中英混杂，按 `%{source}：%{message}` 原样转述。

## 数字、时间与字体

- 价格、数量和时钟在各语言里写法一样（`84,049.95`、`14:03:27`），和托盘一致。
- 紧凑单位（`1.23万`、`12.35K`）、「近 1 小时」这样的时长，按语言的写法在 `src/format.rs`，不进目录。
- Windows 任务栏行情条的 DirectWrite 回退字体按语言选。

## 系统自己的文字

- macOS：`Info.plist` 声明 en、zh-Hans、ja，输入框右键菜单、关于面板这些系统文字能跟系统语言。设置里选了具体语言时，应用把它写进自己的 `AppleLanguages`，等同于在系统设置里给 Candlewick 选语言，下次启动起系统文字也换过去；选「跟随系统」就清掉。只在用户改设置时写，启动时不碰，免得覆盖用户在系统设置里的选择。
- Windows：安装程序有英文、简体中文、日文，按系统语言显示，不认识的系统语言用英文。

## 加一条文字

三个语言的文件同时加（同一种语言里，加在用它的那个 surface）。三种语言齐全、占位符和英文一致由构建检查（见上）。`cargo test` 的 `i18n::tests` 再查一件事：每条消息都有代码在用（Rust 里的 `t!("…"`）；`build.rs` 的 `UNSAID` 列出暂不参与这项检查的 key 前缀。

## 加一种语言

1. `locales/` 下加一个目录，五种 surface 齐全。
2. `i18n.rs`：`Locale` 加变体（和 `ALL`），`Locale::matching` 认它的系统标签。之后编译器会指出每个要为它做决定的 `match`：macOS 的 `remember_language`、Windows 的 DirectWrite 语言名、币安和 OKX 的链接、长桥的 `language()`。
3. 打包：`Info.plist` 的 `CFBundleLocalizations` 加上新语言，安装程序的语言列表也一起加；需要的话设置页语言列表的链接。

## 已知限制

- 切换语言后，已经产生的成句文字保持原来的语言：账户的 `error`、长桥的行情包名，等下一次刷新才换；自选里股票的名字是添加时取的，要重新添加才换。
- 长桥没有日文，日文界面下股票名和长桥的提示是英文。
- 同花顺的名字只有中文，英文和日文界面下也是中文名。
- 繁体中文系统上（之后的首选语言也不是英文、中文、日文时）界面是英文。
